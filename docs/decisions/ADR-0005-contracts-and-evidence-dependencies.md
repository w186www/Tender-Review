# ADR-0005：修正契约事实源和法规参与判断的依赖

- 状态：已接受
- 日期：2026-10-13
- 关联：ADR-0001、ADR-0002、ADR-0004

## 背景

初始State的JSON Schema与Python类型不一致；规则、检索、模型被画成完全并行，无法满足“检索消费候选、分析消费法规”的输入依赖。风险的单一status还混合了证据与人工决定。

## 决策

1. JSON Schema是State唯一字段来源，自动生成TypedDict，并在统一检查中比较结果。
2. 主链按候选发现、针对性法规检索、基于原文与法规的分析、融合、证据校验执行；独立工作单元可并行，有依赖的节点必须等待。
3. evidence_status与review_status独立。人工接受不提高证据强度，所有决定保留操作者、时间和理由。
4. 人工复核后发布不可变结果快照，报告读取该快照；报告完成后任务才能成功。
5. 初始未发布契约升级为v1alpha2。JSON Schema、OpenAPI、任务和相关示例同步升级；已发布制品在升级前执行显式兼容性检查。

## 备选方案

本节为TASK-0015复查补记。维持全并行会违背检索/分析输入依赖；手工维护两份State容易漂移。采用按数据依赖编排、独立工作单元并行、Schema生成类型和自动一致性校验。

## 后果

没有已部署消费者或生产Checkpoint，因此本次无需迁移真实数据。旧status字段不兼容新风险Schema；任何未来导入必须显式映射，不能由AI猜测。Word V2.0中“规则/RAG/LLM直接并行”和先报告后发布的表述由本ADR修正；差异已登记在reference/README.md，正式交付前对齐Word。

本ADR与相关契约优先于旧流程图，但不代表LangGraph节点和业务安全控制已经实现。
