# ADR-0006：独立异常诊断与错误码契约

- 状态：已接受
- 日期：2026-10-13

## 背景

原始异常信息被完全丢弃，500无法定位；运行时错误码也未进入OpenAPI。需要排查能力，同时保持SEC-007的秘密保护。

## 备选方案

1. 原始traceback直接进入普通日志：能排查，但异常消息、源码行和局部变量可能携带秘密，拒绝。
2. 继续丢弃所有异常：安全但不可诊断，拒绝。
3. 普通日志与独立stderr诊断分离，保留异常类型、原因链和安全堆栈：采用。

## 决策

诊断logger不传播到普通logger，仅写专用stderr/sink。保留请求ID、异常类/模块、文件基名、行号和函数；不输出异常消息、完整磁盘路径、源代码行或locals。响应保持统一安全格式。响应已经开始时保留Python原因链，并先记录原始异常的安全诊断。

OpenAPI先定义所有对外错误码，再用类型、正反例和运行时映射一致性测试约束实现。包含11个已定义码及HTTP_ERROR兜底，不能让兜底绕过枚举。

## 后果

新增可排查的独立通道，不等于向用户开放堆栈。生产部署必须对诊断sink实施权限、保留期和访问审计，后续TASK-0012负责。现阶段stderr由服务运维者访问，不提供HTTP查询接口。
