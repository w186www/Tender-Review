# ADR-0007：身份、租户与数据迁移

- 状态：已接受
- 日期：2026-10-13
- 任务：TASK-0004

## 背景

后续文件、任务和模型工具必须使用相同的租户边界。现有 bearer JWT 与项目创建幂等契约需要落地，数据库不能在 API 启动时偷偷建表。

## 备选方案

1. 直接相信请求中的 tenant_id 或角色：无法建立授权边界，拒绝。
2. 首期强依赖尚未指定的企业 OIDC：部署条件未知；后续可在认证适配层替换。
3. 本地账号、短期 JWT、数据库会话校验；SQLAlchemy + Alembic + PostgreSQL：采用。SQLite 仅用于开发和快速回归，不代表 PostgreSQL 验收。

## 决策

账号由受控运维 CLI 创建，不开放注册或网页授权变更。密码使用 Argon2id；签名密钥来自环境，缺失时业务接口关闭，健康检查仍可用。JWT 固定 HS256，校验签名、issuer、audience、exp、iat、sub、tenant_id、jti；每次请求重新读取账号状态、角色和会话，登出立即撤销，不在 Token 中信任角色。

角色矩阵：reviewer 可创建、查询、更新项目；auditor 和 operator 只查询；admin 只查询项目与运维管理，不能自动获得业务写权限。未来文件/任务动作必须单独授予。项目修改采用完整上下文 + expected_version 乐观锁，历史快照只追加。创建幂等键按租户、操作者隔离，重复相同请求返回原始创建快照，复用不同内容返回409。

SQLAlchemy 使用事务级请求 Session，服务与仓库边界显式传 tenant_id；复合外键保证文档/任务不能串租户。PostgreSQL 对项目、版本、文档、任务、幂等和审计启用 FORCE RLS，以事务内 app.tenant_id 为范围；运行账号不得为超级用户或 BYPASSRLS。身份表用于认证，不开放业务查询接口。迁移、账号引导使用独立运维身份，不能将其凭据交给 API。SQLite 使用外键并执行相同应用鉴权，但不提供 RLS。

Alembic 迁移脚本固定表定义，不导入可变 ORM 来建历史表。生产禁用自动建表；首个迁移回滚会丢数据，需备份并停止服务后由运维显式执行。完整权限审批、限流、TLS 与运维防篡改审计仍由后续任务交付。

## 后果

新增登录/登出/身份与项目读写接口；部署需设置 DATABASE_URL 和随机 AUTH_SIGNING_KEY，先迁移和引导再启动。默认无账号、无密钥、无生产弱口令。必须分别验证 SQLite 回归与实际 PostgreSQL 迁移、RLS、外键和并发幂等；不能把 SQLite 结果称为生产数据库验证。
