# ADR-0009：基于仓库的协作与交接

- 状态：已被ADR-0011替代（用户2026-10-14撤销默认跨软件/独立代理流程）
- 日期：2026-10-14
- 任务：TASK-0016

## 背景

实施与审查可能使用不同工作环境，交接不能依赖个人会话记录。已有TASK、契约、验证和PROJECT_STATE，需补齐任务领取、设计审定、提交交接和审查结论，并减少重复读取长历史。

## 备选方案

1. 复制完整会话、各自理解任务：版本难核对、上下文成本高，拒绝。
2. 同时修改同一目录或重复完整实现同一TASK：易覆盖、重复劳动，拒绝。
3. 单个TASK顺序接力，以Git提交、任务派工单和审查记录交接：采用。

## 决策

AGENTS与版本化契约仍是权威来源，不新增第二套运行时任务系统。tasks/active与tasks/completed保持现有Schema；设计/实现/审查阶段写入tasks/dispatch/*.md，提交说明写入tasks/handoffs/*.md，独立审查写入tasks/reviews/*.md。这些是人工阅读的工程记录，不是产品API或领域State。

设计审定、资料盘点、实现和审查按任务明确职责；个人工具安排不属于产品架构，也不决定产品运行时模型供应商。

同一TASK同一时刻只有一个写入者。实施者提交可审查版本，提供确切base/head SHA、验收映射和真实检查结果，停止写入后才交给审查者。审查者核对完整必要调用链、契约和测试，不把绿色门禁代替安全/业务判断。默认先只读审查，修改由实施者处理；紧急修复若改由审查者写，先记录写入权移交。

产品接口、安全边界、法规口径、迁移及恢复等设计先在仓库形成方案/契约/ADR并由指定设计审查者记录通过，再进入实施。这个工程审定不是要求用户重复批准已授权工作。发现阻断问题需给出复现、位置和验收要求；不得修改测试或规则让红色门禁变绿。

具体交接流程见docs/development/collaboration-workflow.md。单独checkout使用任务分支，pull只在干净工作区进行；同目录顺序接力也必须确认前一个写入者已经停止。任务完成由指定最终审查者依据AGENTS和真实验收判断，实施者只标记待审查，不能自审后归档。

## 后果

新增工程记录和模板；Git冲突、审查差异与失败证据可追踪。目录约定与审查状态目前是协作规则，未实现自动锁或自动审批。CI沿用完整现有检查，未删减；生产发布仍遵守release-process.md。
