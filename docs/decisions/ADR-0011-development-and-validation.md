# ADR-0011：单写入者实施与分层验证

- 状态：已接受
- 日期：2026-10-14
- 任务：TASK-0017
- 替代：ADR-0009的默认跨软件分工与强制独立代理关卡

## 背景

用户明确要求恢复原来单一执行者实施方式，并指出资料盘点、文档交接、任务归档反复全测造成浪费。已有代码和未解决的业务问题需保留，开发角色安排不应成为额外批准循环。

## 备选方案

1. 延续强制跨工具接力与独立审查关卡，每阶段全测：增加重复设计、上下文和执行成本，撤销。
2. 为节省时间删测试或降低安全断言：不能确认代码质量，拒绝。
3. 单一执行者负责设计、实现、自检和任务收尾；过程按影响检查、最终代码候选完整验收：采用。

## 决策

AGENTS中的默认跨软件审查关卡撤销；只有明确要求时才增加协作工具或独立审查。实施者的自检如实标为自检，不虚称独立审查。既有D01–D07等问题仍需依据实际验收关闭，不能因角色取消自动变成已解决。保留TASK-0006实现、历史设计/交接/审查记录与业务架构，不回滚成果。

verify.ps1无参数仍执行Full：全部原有测试、静态检查、契约和两个实际启动检查；生成契约一致性也直接检查。新增Quick仅静态仓库/契约/秘密检查；Focused增加Ruff、Mypy和明确选择的测试文件。Focused不允许空选择、越界路径或以Full名义缩小测试，独立JUnit不覆盖完整证据。

开发小步使用Focused；文档/元数据修改使用Quick；最终代码候选与必要专项验收使用Full。Full通过后只有工程记录/归档变化，核对差异并跑Quick即可复用原源码证据；业务代码、契约、数据、配置、依赖、测试或验证脚本变化均需重新Full。失败保留并修复；没有新变化/失败/疑点不重复同一检查。

CI按完整Git差异判断，明确允许的普通文档与任务元数据使用Quick；代码、契约、法规数据、配置、依赖、测试、流程脚本和安全/架构/门禁规则变化均Full。不认识的路径、首次分支或缺失对比历史默认Full；手动运行Full。新增verify-required汇总门禁，Full须baseline/postgres/ingestion全部成功，Quick须快速作业成功；不能把条件不适用或Focused解释为完整验收通过。

## 后果

工程记录减少，不再要求换模型才能继续；真实安全/业务门槛保留。CI仅对普通文档变化免去测试和容器重建，代码候选仍执行全部必过作业。Quick/Focused输出与证据明确区分，人工选错Focused范围会在最终Full被覆盖。新的验证策略本身改变脚本/CI，需要一次Full和针对防误判的测试。
