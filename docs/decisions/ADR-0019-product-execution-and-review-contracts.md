# ADR-0019：产品执行、授权与审查结果契约

- 状态：accepted，2026-10-17，依据用户采纳产品交付总规划并授权本地实施
- 任务：TASK-0028 / TASK-0029，U02
- 先决 ADR：ADR-0002、ADR-0004、ADR-0005、ADR-0007、ADR-0010、ADR-0013、ADR-0017

## 背景

当前契约已有 ReviewTask 生命周期、LangGraph checkpoint、候选覆盖、证据状态及不可变报告，但它们分别服务不同模块。State 还包含已不受数据库约束的 `succeeded`，报告 v2 也没有统一完整度摘要。逐文件外发授权端点已由 FastAPI 实现，OpenAPI 未登记。产品实现需要先明确完成度、覆盖、调用未知、身份及报告含义，同时保留已有结果读取方式。

## 决策

1. 运行生命周期与业务完成度分字段。产品运行状态使用现有持久/API 集合 `queued/running/waiting_human/result_published/failed/cancelled`；`result_published` 只表示不可变审查结果发布，不表示报告已生成或产品级验收通过。`complete/partial/failed/cancelled` 描述业务执行完整度。摄取作业 `succeeded` 仅表示该作业成功，不能映射为文档 ready 或审查完成。
2. 新增版本化 `product-review-execution.v1alpha1` envelope：关联身份、授权决定引用、覆盖、调用状态与摘要；不写入大段正文/响应。现有 ComplianceReviewState v1alpha2 不改字段、不变更旧枚举意义。其 `succeeded` 仅作为旧 State 的历史/开发值，执行 API/DB 不接受该状态；新产品 envelope 不使用它。
3. `complete` 要求覆盖完整或明确不适用、未处理数为零、无未解决截断/饱和且未知模型调用为零。完整零候选跳过语义调用，但需人工 `confirm_no_findings` 后才能发布。失败、取消、部分覆盖、未知调用均不能报告为完整无风险。
4. 调用采用持久 `call_id` 和 `prepared/reserved/dispatched/succeeded/failed/unknown` 结果状态。可能已发送但无可核实结果时记录 `unknown`，保留预算预留，不自动重放；供应商 exactly-once 不作为假设。
5. 发起用户与 Worker 服务身份分离。授权、预算与调度在产品模式以 PostgreSQL 为权威源；每次外部/不可逆副作用前复查当前权限与逐文件授权。撤权影响后续副作用；调用结果未知时不伪造撤回或成功。
6. 语义相关性与法定证据资格独立；检索结果只有在服务端核验来源、发布版本、生效范围、地区/制度和原文定位后才能成为可引用法律证据。真实 RAG 以授权原文和法规候选为输入，输出受限引用供服务端复核。
7. ReviewReport v1/v2 历史读取规则不变。新增 v3 作为带产品完成度/覆盖摘要的新版本；不可变结果、人工决定、审计、模型调用账本和历史报告不回写或按新语义重解释。API 的逐文件授权路径按已实现行为补入 OpenAPI 0.8.0。

## 方案与兼容

先用 JSON Schema/正反例与 OpenAPI 冻结语义，U04/U05 再通过向前迁移增加持久 lease、generation、调用意图/结果及 PostgreSQL 授权/预算表；本 ADR 不分配迁移序号、不执行历史数据迁移。新消费者根据 `schema_version` 选择读取器。v1/v2 数据保留原 bytes/hash 与语义；未知未来版本失败关闭，旧消费者不得接收不认识的新状态枚举。

法规检索保留 BM25/向量混合排序，但资格过滤独立执行；当前未核验法规仍只能作参考。模型、Embedding、索引的真实调用和外发资格仍严格依各自 DEC/D 项，ADR 不授予新的调用、数据或线上权限。

## 备选方案

- 继续只使用单一 `status` 表达生命周期和审查完成：拒绝，因为 `result_published`、部分覆盖和报告生成会被混为一谈。
- 将旧 State/报告直接改成新含义：拒绝，会使严格消费者和历史结果无法辨别原语义。
- 对结果未知的外部调用自动重试：拒绝，可能重复外发或扣费，且供应商不承诺 exactly-once。
- 以检索排名或人工接受作为法规已核验：拒绝，二者不能替代来源、版本、适用性和效力核验。

## 后果

报告、执行记录、模型调用账本、人工结果各有唯一状态责任；将来实现必须保持完整度门禁和身份复核。增加 v3 报告格式及兼容测试成本。未知供应商结果可能需要人工对账，且预算预留可能持续占用；这是避免重复外发和计费不明的预期行为。

## 未纳入本次授权

法规/业务金标签署、支持范围与容量最终承诺、真实供应商调用/正文外发、真实环境迁移/发布仍分别受 D1—D4 阻塞；这不阻止本地契约与 Mock/离线验证。
