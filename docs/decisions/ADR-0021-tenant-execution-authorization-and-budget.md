# ADR-0021：产品模式的租户执行授权、外发登记与预算权威源

- 状态：accepted（2026-10-17，U05/TASK-0028 实施设计）
- 关系：落实 ADR-0019 的产品执行契约；不修改 ADR-0020 的持久调度与未知调用语义。
- 范围：产品模式（PostgreSQL）的逐文件外发授权、机构策略、预算与审计一致性；历史 JSONL/SQLite 账本仅按本 ADR 的受控迁移规则导入。

## 背景

TASK-0027 的 DEC-007 能力使用服务端环境变量、追加式 JSONL 注册表和 SQLite 账本。该组合适用于单机合成数据验证，但不能同时满足：

1. 授权变更与审计同事务提交，失败时没有部分成功；
2. 多 Worker 共享同一预算权威源，原子预留/结算且不重复扣费；
3. 授权绑定租户、项目、文档版本/哈希、用途、供应商、期限和授权人；
4. 机构策略限制供应商与预算，逐文件确认不能扩大机构权限；
5. 撤销优先，并在每次出站前重新检查；
6. 历史账本可审计、幂等、可核账地迁移，不删除、不重置、不双写两套独立额度。

U05 之前，逐文件授权端点先追加 JSONL 再写数据库审计并提交；数据库提交失败会留下已生效但未审计的授权（AUD-09）。SQLite 预算账本只提供单文件原子性，不是产品模式的多 Worker 权威源。

## 决策

### 1. 产品模式以 PostgreSQL 为唯一权威源

产品装配（`DEPLOY_REVIEW_MODE=product-postgres`，入口 `scripts/task0028_product_app.py`）只使用 PostgreSQL 中的机构策略、逐文件授权和预算账户。它：

- 拒绝同时配置 `DEC007_AUTHORIZATION_ID`/`DEC005_AUTHORIZATION_ID`，防止 SQLite 账本与 PostgreSQL 账户形成两套额度；
- 不再把环境变量白名单当作生产放行依据（环境白名单不能绕过逐文件授权）；
- 授权判断在每次冻结运行和每次出站最小化前重新查询数据库；
- 数据库不可读时失败关闭，不回退到 JSONL 或“全部放行”。

DEC-007/JSONL/SQLite 装配保留为本地验证路径，其固定租户假设不再进入产品装配。产品装配的租户由 `PRODUCT_TENANT_ID` 显式提供，缺失即拒绝启动。

### 2. 数据模型

新增五张表（迁移 `202610172000_task0028_execution_authorization.py`）：

| 表 | 职责 |
|---|---|
| `model_execution_policy` | 每租户的机构策略：允许的供应商/用途、预算上限、单次调用上限、授权最长有效期、启用状态 |
| `document_external_authorization` | 逐文件授权：租户、项目、文档、原始哈希、解析版本、用途、供应商、策略版本、授权人/时间、到期时间、撤销人/时间/理由 |
| `model_budget_account` | 每租户+授权身份唯一的预算账户：上限、已预留、已消费 |
| `model_budget_reservation` | 每次调用/Embedding 批次的预留、结算、未知与来源记录 |
| `ledger_import` | 历史账本/注册表导入的来源摘要、计数、金额与报告摘要 |

关键约束：

- 逐文件授权以 `(tenant_id, document_id, document_sha256, parse_version, purpose, provider)` 的部分唯一索引保证同一文件版本只有一个活动授权；
- 撤销只允许 `active → revoked`，授权身份字段不可变，行不可删除；
- 预算账户满足 `reserved_cny + spent_cny <= limit_cny`，账户不可删除；
- 预留状态只允许 `reserved → dispatched → settled/unknown` 或 `reserved → settled/unknown`，结算只能发生一次；
- 所有表启用并强制 PostgreSQL RLS；授权表另有数据库级插入/撤销 actor 策略，要求当前 `app.user_id` 是启用的 reviewer，且与 `approved_by`/`revoked_by` 一致。

### 3. 授权与审计同事务

审核员登记/撤销授权时，`document_external_authorization` 变更与 `audit_event` 在同一数据库事务提交。任一写入失败则整体回滚，不保留“已授权但未审计”或“已审计但未生效”的行。

机构策略由运维 CLI（`scripts/manage_execution_policy.py`）在单事务中更新策略、预算账户和审计事件。策略变更不追溯修改既有授权行；授权行保存 `policy_version`，运行时同时要求当前策略启用、供应商/用途仍在允许集合内。

### 4. 撤销、到期和版本变化

运行时授权判定同时检查：

- 授权行 `state='active'`；
- `expires_at > now()`；
- 当前机构策略启用且供应商/用途允许；
- 冻结快照中的 `document_id`、`raw_source_sha256`、`parse_version` 与授权行完全一致；
- 文档当前哈希与冻结哈希一致。

撤销优先于静态配置：产品模式没有静态哈希白名单；撤销后下一次出站判定即拒绝。已经在途的供应商请求不能被撤回，本文档和界面不得声称“已发送数据可撤回”。撤销竞争以数据库提交顺序为准：当次出站前读到 `active` 的请求可以发出；之后的请求读到 `revoked` 必须拒绝。

### 5. 预算一致性

`PostgresBudgetLedger` 实现现有 `BudgetLedger` 协议，并在 PostgreSQL 中：

- 用单条带条件的 `UPDATE` 原子预留；两个 Worker 竞争最后一个额度时只有一个成功；
- 结算在行锁内校验 `reserved`/`dispatched` 状态与上限，重复结算被拒绝；
- 成功结算写实际费用；失败/未知用量调用 `consume_reservation` 按预留上限记入 `unknown`，不释放、不清零、不自动重发；
- 调用发出前标记 `dispatched`；重启时对 `dispatched` 且对应审查运行已失效的预留按未知处理，对从未发出的 `reserved` 预留才允许在明确超时后释放；
- 预留可通过 `call_id` 幂等：同一调用身份重复预留返回原预留，不重复占用额度。

Embedding 批次与 LLM 调用共用同一租户账户，不建第二套额度。U04 的 `ReviewModelCall` 仍是调用结果未知的权威记录；预算预留通过 `call_id` 与它关联，接管 Worker 把调用标为 unknown 时同步把对应预留标为 unknown。

### 6. 历史迁移

`scripts/migrate_execution_ledgers.py` 只读打开来源 SQLite/JSONL，计算来源 SHA-256，在单个目标事务中：

- 保留来源请求 ID 作为 `reservation_id`；
- `settled` 按原费用导入；`reserved`/未知状态一律映射为 `unknown` 并按预留上限计入消费（不释放、不推测为零）；
- 任何畸形/无法映射的记录使整次导入失败并输出异常清单，不静默跳过；
- 目标账户消费额由导入行求和校验，重复运行不重复计数；
- 注册表 approve/revoke 行按时间顺序映射到逐文件授权；无法解析到租户内文档的行进入异常清单；
- `ledger_import` 记录来源摘要、计数、金额、报告摘要和导入人。

真实运行账本、生产数据库和受保护历史原件不在本 ADR 授权范围内。切换需要单独批准：先停外发、备份、在受保护副本上演练核账，再切换；回退时关闭外发并保留新账本，不恢复或删除历史额度。

### 7. 隐私、密钥与保留

- 出站正文继续经过最小化和 PII 预检；新增表格相邻单元格、跨段落标签-值、跨段敏感信息的反例。
- 日志使用允许列表字段，诊断只记录异常类型/栈位置，不记录消息、正文、请求体或密钥。
- 供应商密钥只从服务端受保护配置读取，不写入数据库、审计、响应或前端。
- 授权、预算、导入和审计记录按审计证据保留，不提供运行时删除接口；真实删除/保留期限需 D 项批准后执行。
- 备份必须包含业务数据库、对象存储、法规发布/索引、模型状态卷与审计；恢复后先关闭外发并核账，未完成核账不得重新放行外发。

## 兼容性

- OpenAPI 在 0.9.0 上加法升级到 0.10.0：逐文件授权请求新增可选 `purpose`、`provider`、`expires_at`，响应新增可选授权身份字段；新增撤销操作。旧客户端只发送 `reason`/`confirmed` 仍然有效，服务端按当前策略填入默认值。
- 数据库迁移只新增表，不改既有表；旧 SQLite/JSONL 账本和注册表不被读取、覆盖或删除。
- 产品模式是显式装配选择，不改变现有 `offline`/`authorized-real` 部署行为；切换需 D4 操作授权。

## 备选方案（被否决）

- **继续以 JSONL 注册表为产品权威源**：无法与数据库审计同事务，无法可靠处理撤权竞争和多 Worker 一致性。
- **JSONL 与 PostgreSQL 双写**：故障时必然出现两套状态，且无法证明哪一套是权威。
- **迁移时把历史 `reserved` 直接释放**：可能已发生供应商费用，释放等于无依据恢复额度。
- **用环境变量白名单扩大生产授权**：绕过逐文件确认，违反 U05 的明确边界。

## 后果

- 产品运行需要数据库迁移、受限运行角色授权和运维策略配置；缺失时失败关闭。
- 历史账本导入是一个显式的、可核账的切换活动，不由应用启动自动执行。
- 在途请求的隐私和费用边界仍是“发出后不可撤回”，只能阻止后续出站并保留未知费用。
- 真实供应商调用、真实内容外发、生产迁移和线上操作仍分别需要 D3/D4 批准；本 ADR 只批准本地实现、合成演练和验证。
