# ADR-0022：法规采用政策与引用语义

状态：accepted（实现 DEC-009）。
日期：2026-10-18。

## 背景

项目此前只有“独立核验且期限内”的条款才能成为正式依据。42 个版本未核验、唯一已核验版本于 2026-10-14 到期，导致真实文件审查只能显示参考条款、可引用正式依据为 0。用户决定本版直接采用现有法规库，但仍要求不伪造 verified、不冒充专家、不自动认定违法。

## 决策

1. 新增版本化 `config/legal/adoption-policy.json`，冻结清单身份、版本集合、索引身份、采用政策 ID 和“未做独立法律核验”的声明。
2. 新增 `config/legal/rule-law-bindings.json`，由工程配置流程校对规则、库内版本、条文的原文存在性和理由；`asserted_by=engineering-config`，不是人工裁定。
3. 法规命中新增 `adoption_status`（`project_adopted`/`not_adopted`）；检索结果新增 `adopted_evidence` 和 `adoption_policy_id`。
4. `citable_evidence` 保持“独立核验且资格满足”的严格含义；采用条文不并入正式证据集合。
5. 采用条文可以进入模型候选、检索参考、报告引用和前端展示，但必须同时显示版本状态、未确认原因和“项目采用库内版本（未经独立法律核验）”。
6. 服务端继续校验引用 ID、原文、版本、来源、发布/修订和项目适用条件；模型引用未暴露 ID 仍判无效。
7. 采用政策与清单/索引身份不一致时失败关闭；旧运行/旧报告按原快照读取，不重解释。

## 兼容性

- 新增字段均有默认值；无政策文件的测试/旧装配保持 legacy 行为。
- `LegalResult` 仍是 v1alpha5 的加法字段；`EvidenceRef` 新增可选 `adoption_status`；报告 v3 的 `assessment_scope` 新增可选政策字段。
- 旧报告不补造采用政策，不重写历史核验状态。

## 风险与边界

- 采用政策不是法律核验；参考条款的相关性和适用性仍需人工复核。
- 规则—法规关联是工程配置，不是专家意见；关联质量需要冻结集和人工抽检。
- 采用库版本的身份随清单/索引变化必须重新生成，否则校验失败。
- 本 ADR 不改变“不得自动认定违法”和“未核验资料不得冒充 verified”的原则。

## 后果

- 审查报告可以展示项目采用的库内法规参考，同时保留“未做独立法律核验”的明确限制；正式 `citable_evidence` 仍为 0 时不会伪装成已核验依据。
- 规则—法规关联可在工程配置中维护和审计，但每条都必须有真实规则、库内版本、原文条文和理由；配置变化需要版本化记录。
- 清单/索引变化会使采用政策身份失效并失败关闭，必须重新生成政策文件，防止静默采用不同语料。
- 人工复核责任和组织的数据治理责任仍由使用方承担；本 ADR 不改变不得自动认定违法的原则。

## 备选方案

1. **继续只允许独立核验条款成为依据**：证据最严格，但本版法规库几乎全部不可用，真实文件只能显示 0 条可引用依据。未采用。
2. **批量把 `verification` 改成 verified 或延长 `verified_through`**：会让系统声称未实际完成的核验，违反用户“不得伪造 verified/裁定人/日期”的要求。拒绝。
3. **采用库但只做完全非结构化参考**：不能满足模型引用、报告追溯和规则关联的需求。未采用。
4. **本 ADR 的采用政策 + 严格引用/适用性重核 + 工程配置关联**：在保留真实性和可追溯性的前提下让库内条文参与审查。采用。
