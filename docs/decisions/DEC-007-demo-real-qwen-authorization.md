# DEC-007：云端演示的真实 Qwen 受控授权（申请草案）

状态：**proposed，等待用户明确批准**。批准前不得执行任何供应商调用。

本申请由 TASK-0026 部署实施提出。与 DEC-005、DEC-006 **相互独立**：那两条授权的额度已按记录消耗，
本授权不重置、不回收、不叠加其历史计数，只新增一条独立授权记录。

## 一、为什么需要新授权

目标部署（阿里云 ECS `47.83.132.211`）希望让面试官看到**真实 Qwen 语义审查**，而不是
确定性的协议网关输出。现有两条授权无法复用：

- `DEC-005-2026-10-15`：30 次 LLM / 200 批 Embedding / ¥20 —— 记录为已消耗。
- `DEC-006-2026-10-15`：15 次 LLM / **0 批 Embedding** / ¥5 —— TASK-0023 已用掉 10 次。
- 外发还受**文档 SHA-256 白名单**约束（`AuthorizedTenderMinimizer`），
  白名单参与 `scope_sha256` 绑定账本，未登记的文档分段一律拒绝。新文件天然不在白名单内。

## 二、部署层面的硬前提（本轮核查发现）

法规检索的语料向量与查询向量都存放在本地 SQLite 缓存中，且**缓存优先**：
`legal/vector_index.py::embed_query` 未命中才调用 provider，`::build` 同理。

- 历史真实运行能在 0 批 Embedding 上限下完成，是因为复用了开发机上已填充的缓存文件
  （该文件在 `.verification/private/` 下，未入库）。
- **全新主机没有这份缓存**，启用真实检索会立即产生 Embedding 请求；额度为 0 时检索会失败。

因此本申请要求二选一，请明确选择：

- **方案 A（推荐，成本最低）**：真实 Qwen 只用于 `semantic_analysis`；法规检索继续使用
  仓库既有的本地字符向量实现（`LegalRetriever` + `CharacterEmbedding`），不挂载真实检索器。
  此时只需 LLM 额度，**Embedding 上限可为 0**，且在全新主机上可直接工作。
- **方案 B**：同时启用真实向量检索。需要额外的 Embedding 批次额度用于在目标主机上重建向量索引；
  覆盖面受批次上限约束，且首次构建耗时较长。以当前法规库规模（43 版本 / 3120 片段），
  历史记录显示真实向量的覆盖仅为 10/3120 片段，**不宣称整库向量化**。
