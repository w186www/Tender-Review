# DEC-008：产品交付 D1—D4 与持续实施授权（2026-10-18）

状态：accepted（用户于 2026-10-18 明确指令）。
适用范围：TASK-0019、TASK-0029、TASK-0028、TASK-0012/0013/0014 中与 D1—D4 相关的实施、验证、提交、服务器备份/演练和候选发布。
不适用范围：用户独立验收、专家金标签署、逐条法规内容确认、超出既有额度的付费调用、破坏性数据操作。

## 1. 授权内容

### D1 首版支持范围

用户批准首版实现及验收目标：

- 自托管单机、多租户、人工复核；
- PDF、DOCX、PNG、JPEG；
- 单文件最大 10 MiB、300 页，其中 OCR 最多 30 页；
- 保留现有五类审查能力；
- 继续执行支持矩阵中的文件安全、解析资源和质量限制。

支持范围必须经过验证。超限、解析不可靠、覆盖不足时，必须明确拒绝、转人工或显示部分完成，不得静默截断后显示全部审查完成。性能/容量按既有 NFR 验证；缺少定义的指标采用保守、可测量的服务档位，测试前登记条件，测试后报告实测上限，不虚构承诺。

### D2 法规核验与专业标签

用户是最终内容确认责任人。工程侧可以：

- 读取公开官方来源，核对法规原文、版本、生效时间和适用范围；
- 完成法规/规则生命周期、绑定校验、参考检索与正式证据资格区分；
- 准备法规核验、规则绑定、风险/非风险及法律适用标签草案；
- 为每条待确认内容列明原文位置、依据、适用前提、判断理由和不确定性。

不得冒充专家、伪造人工裁定人、代替用户签署、把模型标签改称专家金标、把一般实施授权当作逐条内容确认，或自动延长核验期限。缺少专业裁定时保留真实缺口，不停止其他工程工作，也不能声称专业效果验收通过。

### D3 真实模型、Embedding 与 RAG

允许使用项目既有百炼北京供应商和已配置模型进行受控真实调用。允许数据：

- 合成测试文档；
- 测试必需的公开法规正文；
- 用户明确提供并逐文件确认外发的自有招标文件。

不得自行引入第三方保密客户文件。预算沿用既有累计边界：总费用人民币 200 元、LLM 2000 次、Embedding 2000 批，不是新增额度；必须扣除历史消费、预留和 unknown；迁移前后统一核账；不通过新 scope、账户、数据库或重启恢复额度；保持原子预留、有限重试、并发限制和 unknown 不自动重放；不足时停止相关付费活动，不自动充值扩额。

生产网页仍执行机构策略和逐文件授权；本次授权不取消这些控制。凭据只在受保护配置中使用，不写日志、提交和交接正文。

### D4 服务器演练与发布

允许使用项目现有 ECS、部署入口及账户，不购买新云资源或新付费服务。从本次执行开始至用户下次验收前，允许必要的项目维护、兼容迁移、服务重启及候选发布。顺序：

1. 核对实际服务器、运行版本、配置及在途任务；
2. 完整备份数据库、对象、索引、授权、预算及审计；
3. 校验备份并在隔离目标演练恢复；
4. 演练产品模式与历史账本迁移，核对费用、未知预留及授权映射；
5. 部署经过验证的稳定候选；
6. 在真实服务器跑通网页登录、PDF 上传、解析/OCR、真实模型审查、人工复核和报告下载；
7. 验证权限、失败提示、任务恢复、TLS 和必要监控；
8. 如失败，按已验证方案回退，保全新数据和账本。

禁止删除现有业务数据、生产库破坏性降级、覆盖原账本、销毁备份或恢复旧额度。破坏性恢复仅允许在已确认隔离的演练目标执行。允许向已配置且明确属于用户的渠道投递告警测试；没有接收渠道时完成系统内告警并记录外部投递缺口，不假装送达。

### Git 与治理

允许必要的提交、推送、PR、正常冲突处理、通过正式门禁后合并，以及发布可追溯版本。不强推、不绕过分支保护或 CI、不删除未知分支和历史成果。`question.txt` 保持私人文件。不提交密钥、私人账本或敏感证据。部署版本必须对应源码 SHA、镜像、迁移和配置身份。

## 2. 明确不构成的事项

- 不构成用户对任何法规条文、规则—法律绑定、风险/非风险标签的逐条确认；
- 不构成专家金标、专业法律意见或“系统自动认定违法”；
- 不构成用户独立验收或正式交付完成；
- 不扩展 DEC-002/005/006/007 的历史范围，不重置任何历史账本；
- 不授权删除现有业务数据、备份或做不可逆生产降级。

## 3. 记录要求

每笔真实调用按既有账本/审计记录累计；每次部署记录源码 SHA、镜像 ID、迁移版本和配置身份；每次备份记录路径、SHA-256、恢复演练结果；所有未完成条件和真实缺口在 `PROJECT_STATE.md` 与任务记录中保留。
