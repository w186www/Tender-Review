# 单写入者开发与验证

依据ADR-0011，默认由当前执行者按正式TASK完成必要设计、代码、测试、排错、自检和任务收尾；不默认增加额外派工、独立批准或跨软件往返要求。原业务LangGraph设计保留。

## 工作步骤

1. 读取AGENTS、PROJECT_STATE、docs/index、正式TASK及必要引用，检查实际分支和未提交内容。
2. 明确契约和验收，再完成实现；只为必要长期决策写ADR，不先生成整套重复大文档。
3. 开发中按影响检查，修复失败。代码稳定后完整验收一次，必要专项检查另行运行。
4. 对照验收自检边界与未覆盖行为，保留已发现问题；自检不能冒称独立审查。
5. 通过后填写任务证据、更新PROJECT_STATE/CHANGELOG、归档；若只改工程记录，跑Quick确认引用/状态即可，保留并说明完整验收对应源码版本。

只在明确要求时增加协作工具或独立审查。历史任务的实现和问题记录保留，后续按实际状态、问题与局部验收继续处理。

## 验证档位

| 情形 | 命令 | 范围 |
|---|---|---|
| 普通文档、资料草案、任务状态/证据记录 | `./scripts/verify.ps1 -Mode Quick` | 仓库/任务/依赖、契约正反例、生成一致性、秘密扫描 |
| 当前模块编码或修复 | `./scripts/verify.ps1 -Mode Focused -TestPaths tests/test_legal_retrieval.py,tests/test_legal_runs.py` | Quick + Ruff/Mypy + 明确的相关测试文件 |
| 最终代码候选、公共契约/权限/迁移/依赖等变化 | `./scripts/verify.ps1` | 全部测试 + 实际HTTP启动；任务专项实证另执行 |

PowerShell传多个TestPaths用数组（示例中的逗号）；不支持用目录、空选择或越界路径模糊缩小范围。Focused失败或影响范围不清时扩大到Full，不删断言/检查。

Quick不运行Pytest或启动服务；Focused的结果写pytest-focused-result.xml，不能冒用为完整验收；Full维持pytest-result.xml。完整通过后没有代码变化、失败或新疑点就不重复执行。

## CI与证据复用

CI完整对比提交：普通文档/任务元数据走Quick，代码/数据/配置/契约/依赖/测试/脚本、安全/架构/门禁规则以及未知变化走Full；缺少比较历史和手动触发也Full。Full保留原baseline、真实PostgreSQL和文件处理三作业。verify-required检查实际适用作业全部成功，建议作为分支保护必过项。

本地Full对应源码SHA与工作区差异、命令、计数和结果需写清；远程CI另绑定URL/SHA/作业。后续只更新交接或归档记录时说明两个版本的差异，并跑Quick，不把原SHA称为当前HEAD。设计或实际语义改变必须重新审视影响；运行时输入、配置、契约等改变不能作为纯文档复用证据。

目前是显式档位与CI选档，没有未经验证的自动测试缓存或自动“审查通过”。历史跨软件记录只用于追溯问题，不再约束工作角色。
