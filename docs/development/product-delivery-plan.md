# A. 总体交付判断

## A1. 最终产品定位

建议将最终交付目标定义为：

可自托管部署、支持租户隔离、具有可靠执行与恢复能力的招标文件 AI 辅助合规审查系统。系统提供安全解析、确定性检查、模型疑点发现、法规匹配、可追溯证据、人工复核和报告交付，由授权人员承担最终审查决定。

保留现有五类审查能力、真实 Qwen、Embedding、法规检索、人工复核及报告导出，不以降低功能换取交付。

产品必须明确支持范围，包括文件格式、文档规模、采购制度、法规覆盖、用户角色和运行负载。超出范围的输入明确拒绝或进入人工处理，不能显示为“审查完成”。

当前“法规仅作待核验参考”的 Demo 边界，与“结果具有可信法规依据”的产品目标有差距。产品版本需要建立真实法规维护和核验责任，但不要求先核验全部 43 个版本。先覆盖承诺支持的业务范围，其余继续作为参考展示。

## A2. 产品完成定义

| 交付维度 | 必须达到的状态 |
|---|---|
| 业务闭环 | 合法文档完成上传、解析、确认、审查、复核、发布和报告；零候选为正常结果 |
| 审查真实性 | 真实模型参与约定发现与分析；离线替身、响应重放和真实调用明确区分 |
| 法规与证据 | 原文、法规版本、适用范围、核验状态和推理依据可追踪；参考不冒充确认依据 |
| 业务质量 | 在冻结、有人工标签的验收集上达到既有阈值，报告有效分母及严重风险表现 |
| 执行可靠性 | API 超时、Worker/API 重启、重复请求和模型异常有明确状态与恢复方式 |
| 安全与隐私 | 服务端鉴权、租户隔离、逐文件外发授权、预算、敏感数据保护和审计有效 |
| 产品操作 | 正常审查、校正、复核、失败处理和报告下载可通过产品界面完成 |
| 部署与运维 | 可依文档安装、升级、备份、恢复、监控和回退；关键故障能通知负责人 |
| 工程交付 | 代码、契约、迁移、任务、构建、部署版本和验收证据对应一致 |
| 最终验收 |执行者提供候选和证据；用户独立验收后决定是否接受交付 |

任务全部 completed、CI 全绿或一次 E2E 成功，均不能单独证明产品完成。

## A3. 整体技术路线

保留 FastAPI、PostgreSQL、LangGraph、现有前端、ClamAV、受限解析容器、Tesseract、规则与 Skill、模型网关、Qwen/Embedding 接口、BM25、持久向量索引、法规发布快照、人工决定、不可变结果及 Word/PDF。

在此基础上补齐四项能力：

1. 持久执行与授权一致性：调度、Checkpoint、外发授权、预算和审计形成一致运行机制。
2. 审查业务内核：补齐解析质量、发现覆盖、法规检索与语义分析之间的断层。
3. 产品操作与运维闭环：覆盖正常、失败、部分完成、恢复及版本升级。
4. 业务验收与交付证据：冻结样本和真实环境证明业务能力，不只证明组件运行。

不预设更换模型、OCR、向量数据库或 Agent 框架。只有现有方案在约定验收中有明确无法解决的缺口时，才提出带对比证据的替换。

## A4. 设计决策依据

### 继续遵循的现有约束

- LangGraph 表达流程，State 以引用为主。
- API、调度、业务编排职责分开。
- 供应商调用经过适配接口和模型网关。
- 原文、法规发布、输入快照和结果有版本及来源身份。
- 模型输出不能授予权限。
- 未核验、不适用或无法定位的法规不能成为确定结论依据。
- 人工决定与独立证据状态分开。
- 保留历史结果和验收，不通过改写历史消除问题。
- 单一实施者负责代码写入，不恢复多代理批准循环。

### 本规划推荐采用、需要落入正式设计的方案

| 事项 | 推荐方案 | 理由 |
|---|---|---|
| 持久调度 | 复用 PostgreSQL，接通作业、lease 和 Checkpoint | 不新增队列平台，解决实际接管缺口 |
| 产品授权和预算 | PostgreSQL 为产品模式权威源；历史 JSONL/SQLite 保留并受控迁移 | 事务、租户范围、并发及审计一致 |
| 法规检索 | 分开参考相关性排名与正式证据资格 | 保留语义召回，不放宽法律证据门禁 |
| 模型发现 | 覆盖驱动的有界分批；饱和可识别、细分、报告 | 消除每批 3 项的隐性能力上限 |
| 模型分析 | 模型接收经授权原文与法规候选，返回受限引用，服务端重新核验 | 补齐真实 RAG，不直接采信模型法律判断 |
| 结果表达 | 分开事实检查、模型评估、证据资格、人工决定 | 不混淆引用真实、适用正确和违法认定 |
| 发布部署 | 优先完成现有单机部署可靠性与安全边界 | 暂无依据先建设多节点平台 |

总体方案采纳后，这些是执行者的技术基线；应补充正式 ADR/契约，不能把规划冒充既有批准记录。

**前置与范围：** U02；任务 A；审查 API、ReviewEngine、摄取 Worker、调度、持久模型/迁移。

**方案与顺序：**

1. API 校验并冻结输入、持久登记意图，及时返回，不等待整段模型流程。
2. 摄取轮询同时选择可运行作业及 lease 过期的 running 作业。
3. 复用审查运行记录形成持久队列，增加必要 lease、执行代次、动作及调度时间。
4. 原子领取与心跳续租，旧 Worker 被接管后不能写入。
5. 明确 start/resume/retry/cancel 及幂等。
6. 从冻结输入和 Checkpoint 恢复，不重建身份。
7. 零候选跳过不必要语义调用，进入人工确认/发布。
8. 持久记录调用身份、预留、执行和结果；成功响应不重复调用；可能已发出但结果未知保留预留、不自动补发；不假定供应商 exactly-once。
9. JWT 过期与后台执行授权分开。Worker 重检当前账户/资源权限，不伪造长期 Session；显式撤权阻止后续副作用。

**验证与证据：** 真实 PostgreSQL/容器，覆盖领取、解析、模型请求、结果保存、人工等待及发布前后重启，并发领取、重复投递、取消竞争、零候选和未知调用。

**禁止/完成/回退/后继：** 不改状态为成功处理孤儿任务。部署入口实际接管才完成，不仅直接调用引擎。回退先停领取、处理在途，保留 Checkpoint/调用；不兼容禁止直接回旧执行器。U05/U10/U11 依赖。

## U05｜租户执行授权、外发、预算与隐私一致性

**目标与依据：** 解决 AUD-09 及固定演示租户、分散授权和审计。

**前置与范围：** U02/U04；任务 A；身份、授权 API、网关、预算、审计和迁移。

**方案与顺序：**

**验证与证据：** 全资源跨租户负向；登记提交失败、撤销竞争、并发预算、历史迁移、未知费用、秘密日志、隐私反例和合成出站载荷。
