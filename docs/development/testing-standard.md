# 测试与评估规范

| 层级 | 目标 |
|---|---|
| 单元测试 | 规则、领域对象、权限、合并和证据判定的关键分支 |
| 契约测试 | OpenAPI、JSON Schema、事件、模型与 OCR 适配器 |
| 集成测试 | 数据库、对象存储、Redis、向量检索、Checkpoint |
| 端到端测试 | 上传到报告和人工复核的完整路径 |
| 安全测试 | 越权、注入、恶意文件、秘密、依赖和 API 边界 |
| 评估集 | 风险召回、准确率、证据、页码、重复率和稳定性 |
| 恢复测试 | Worker 中断、超时、限流、数据库恢复和版本回滚 |

测试数据默认使用合成或脱敏文件。真实样本进入受控目录并附使用授权和保留期。任何模型输出断言应检查结构和业务不变量，避免依赖长文本逐字相等。

M0门禁必须包含负向回归：损坏YAML、非法Schema、无法解析的引用、响应字段冲突、State漂移、无证据completed任务与空测试集。没有收集到测试时返回非零退出码。

统一命令执行Ruff、应用Mypy和Pytest。供应商适配器、实际法规、越权、恢复、部署和性能测试按roadmap逐阶段加入，不能用M0字段测试替代全局AC。
