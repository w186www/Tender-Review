# 测试与评估规范

| 层级 | 目标 |
|---|---|
| 单元测试 | 规则、领域对象、权限、合并和证据判定的关键分支 |
| 契约测试 | OpenAPI、JSON Schema、事件、模型与 OCR 适配器 |
| 集成测试 | 数据库、对象存储、Redis、向量检索、Checkpoint |
| 端到端测试 | 上传到报告和人工复核的完整路径 |
| 安全测试 | 越权、注入、恶意文件、秘密、依赖和 API 边界 |
| 评估集 | 风险召回、准确率、证据、页码、重复率和稳定性 |
| 恢复测试 | Worker 中断、超时、限流、数据库恢复和版本回滚 |

测试数据默认使用合成或脱敏文件。真实样本进入受控目录并附使用授权和保留期。任何模型输出断言应检查结构和业务不变量，避免依赖长文本逐字相等。

M0门禁必须包含负向回归：损坏YAML、非法Schema、无法解析的引用、响应字段冲突、State漂移、无证据completed任务与空测试集。没有收集到测试时返回非零退出码。

默认./scripts/verify.ps1执行完整Full；供应商、实际法规、越权、恢复、部署和性能专项按roadmap加入，不能用字段检查替代全局AC。

## 过程检查与最终门禁

- Quick：资料草案、普通文档、任务状态与证据记录。仓库依赖/证据、所有契约正反例、生成一致性和秘密检查；不执行Pytest或服务启动。
- Focused：实现/修复小步，明确-TestPaths对应相关test_*.py文件；执行Quick、Ruff、Mypy和指定测试。影响范围不清或涉及公共安全/契约时扩大验证。
- Full：最终代码候选、合并前代码验收、发布和关键公共改动。所有已有测试及实际HTTP检查保留，任务必需专项另验收。Focused/Quick不能代替最终代码验收。
- Full通过后只更新工程记录或归档，检查代码/契约/数据/配置/依赖/测试/脚本无变化并跑Quick，引用原源码证据；无需归档后再全测。代码等实际变化、失败或新疑点才重跑Full。

CI普通文档/任务元数据Quick；代码与未知影响Full，缺比较历史/首次分支/手动运行Full。验证策略与安全/架构规则变化也Full。verify-required要求所有适用作业成功；Quick、Focused结果明确注明范围，保留完整与局部JUnit独立文件。部署/迁移/权限/解析等专项按影响执行，不能用本地替身冒充真实集成。

具体命令与证据复用规则见development-workflow.md。原有测试、断言和CI完整代码门禁没有删除或放宽。
