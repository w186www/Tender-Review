# 验收标准

| ID | 验收项 | 通过条件 |
|---|---|---|
| AC-001 | 文件接入 | PDF、DOCX 和扫描件样本均可入库，非法文件被拒绝并有安全事件。 |
| AC-002 | 原文定位 | 黄金样本的风险均能定位到页码和文本片段，引用片段与原文一致。 |
| AC-003 | 审查链路 | 五类 Skill 可执行，规则、检索、模型、融合和证据校验结果可追踪。 |
| AC-004 | 证据约束 | 没有有效法规证据时不输出“确定违规”，而是降级为疑似或证据不足。 |
| AC-005 | 人工复核 | 审核员的接受、修改、驳回和理由进入最终报告及审计。 |
| AC-006 | 报告 | Word/PDF 报告内容完整、编号稳定、中文排版可读且可回到证据。 |
| AC-007 | 恢复 | 模拟模型超时和 Worker 重启后可恢复，已完成节点不重复执行副作用。 |
| AC-008 | 租户隔离 | 跨租户读取、下载、检索和导出全部被拒绝并记录。 |
| AC-009 | 注入防护 | 恶意文档不能改变工具权限、读取秘密或触发外部写操作。 |
| AC-010 | 模型替换 | 至少两个兼容适配器通过同一套结构化输出契约测试。 |
| AC-011 | 工程门禁 | 单元、契约、集成、安全、依赖和秘密扫描无阻断缺陷。 |
| AC-012 | 可交接性 | 新开发者仅依据仓库文档可启动环境、运行验证并继续一个任务。 |

## 质量阈值

具体数值以 `evals/thresholds.yaml` 为可执行来源。阈值调整必须保留评估结果并记录决策，禁止为了单次发布临时降低阈值。
