# 功能需求

状态：基线草案（v1alpha1）

| ID | 需求 | 最低可验收结果 |
|---|---|---|
| FR-001 | 用户可创建项目并录入采购类型、项目类型、地区、行业、金额和适用制度。 | 上下文字段被版本化保存并进入审查 State。 |
| FR-002 | 系统接收 PDF、DOCX 和常见扫描文件，保留文件哈希、页码、章节、段落、表格和坐标定位。 | 解析结果可回到原文页和位置。 |
| FR-003 | 系统识别项目上下文，并允许审核员修正低置信字段。 | 自动值、置信度、人工值和修改记录均可查询。 |
| FR-004 | Supervisor 根据上下文选择资格、技术参数、评标、合同和程序审查 Skill。 | 任务记录实际启用的 Skill 及版本。 |
| FR-005 | 规则引擎产生带规则版本、原文定位和解释的候选风险。 | 规则结果可独立复现。 |
| FR-006 | 法规检索按适用范围、效力、地区、时间和条款召回证据。 | 每项证据含法规名、条号、版本、原文和来源。 |
| FR-007 | 模型语义分析必须返回结构化结果，不得直接写最终审查结论。 | 输出通过 Schema 校验，失败时进入重试或人工复核。 |
| FR-008 | 系统融合规则、检索和模型结果，完成归并、去重、冲突标注与风险分级。 | 相同问题不重复展示，冲突不被静默覆盖。 |
| FR-009 | Evidence Checker 校验原文、法规、时效和推理强度。 | 输出 `confirmed`、`suspected` 或 `insufficient_evidence`。 |
| FR-010 | 审核员可接受、修改、驳回风险，并填写理由。 | 所有操作有操作者、时间、前后值和理由。 |
| FR-011 | 系统生成含摘要、问题、定位、依据、建议和复核状态的 Word/PDF 报告。 | 报告条目可追溯到已发布的审查结果。 |
| FR-012 | 任务可暂停、恢复、取消和失败后有限重试。 | Worker 重启后从 Checkpoint 恢复且不重复产生副作用。 |
| FR-013 | 管理员可版本化管理法规、规则、Skill 和模型配置。 | 草稿、发布、停用和回滚均留有审计记录。 |
| FR-014 | 审计员可按租户、项目、任务、人员、动作和时间检索审计事件。 | 导出结果不包含密钥或未授权正文。 |
| FR-015 | 系统记录模型、Token、延迟、费用估算、缓存与降级路径。 | 每次模型调用均关联任务、节点和配置版本。 |

## 首期范围

首期交付覆盖工程、货物和服务类招标文件的辅助审查。系统输出是专业复核材料，不自动代替最终法律意见和招标人的法定责任。
